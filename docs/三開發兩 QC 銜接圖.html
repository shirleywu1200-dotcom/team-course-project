模式 A：3 位開發與 2 位 QC 在 W1 到 W5 各做什麼，QC 何時寫測試、何時驗收，以及一個 PR 從開始到合併的路徑。依據 todo.md 第 5、6 節。

開發實作（色條 = 該開發） QC 寫驗收測試（色條 = 被測的開發線） QC 驗收／演練 與開發同步或落後 閘門

圖中要注意的三件事

Dev-A 是關鍵路徑

第一片只含 DDL、觸發器、write_event、樂觀鎖，刻意切小。Dev-B 在這之前只做純函式，不是閒置。

QC 領先並非處處成立

Phase 5、9、10 的驗收測試與開發同波次，Phase 11 與 Phase 12 的前端流程測試要到 W3 才補。獨立性還在，但先紅再實作的好處打折。

最重的橫向依賴

Dev-A 的 Phase 4 與 Dev-B 的 Phase 7 都呼叫 adjust_due。簽名在開工會凍結，Dev-B 用替身驗證呼叫參數。
