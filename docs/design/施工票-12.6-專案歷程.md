## 1. 本票核心裁定｜共用歷程元件的「reuse 邊界」（最重要，先讀）

12.6 **重用** #55 已在 main 的共用 `HistoryEventRow`／`HistoryEventList`／`SourceEvidence`，**不 fork、不另建副本、不與 12.3 頁面互 import**。但 12.6 是「專案／全域」情境，比 12.3「單一任務詳情」多三個互動，而 main 上的 `HistoryEventRow` 目前（阿想已核對）：

- ✅ **已攤** `project_name`（`{item.project_name && …}`）、有效註記、前後值、來源 → 直接用。
- ✅ 補／改註記鈕靠 optional `onAnnotate` 控制；**12.6 唯讀、不傳 `onAnnotate` → 鈕自動隱藏**。
- ❌ **缺**：`task_title` 連任務詳情、`project_name` 連專案歷程、`batch_id` 列標籤捷徑（FR-HIS-06＋BatchFilter 要這三個）。

**裁定：對共用 `HistoryEventRow` 做「加法式、選用 prop」擴充，照既有 `onAnnotate?` 同一模式，三個全選用、全由 12.6 頁面注入；未注入時列的輸出與現狀逐 byte 不變（12.3 不受影響）。** 元件維持純展示、不 import router；導航由 12.6 頁面負責。

新增三個 optional callback（型別用生成型別的 `HistoryItemOut` 欄位）：

| 新 prop（皆 optional） | 給值時 | 不給值時（即 12.3 現狀） |
| --- | --- | --- |
| `onOpenTask?(taskId: number)` | `task_title` 在 `task_id≠null` 時渲染為可點控制 → 呼叫 callback 導向 `/tasks/:taskId` | `task_title` 維持純文字 `<h3>`，與現狀一致 |
| `onOpenProjectHistory?(projectId: number)` | `project_name` 在 `project_id≠null` 時渲染為可點控制 → 導向 `/projects/:projectId/history` | `project_name` 維持純文字 `專案：…`，與現狀一致 |
| `onBatchFilter?(batchId: number)` | `batch_id≠null` 時**才**渲染「批次 #N」標籤捷徑 → 呼叫 callback 把 batch_id 帶入 draft 並套用 | **完全不渲染批次列**（12.3 視覺不變） |

- 三者皆「callback 在才渲染互動、不在則維持現狀」，故 **12.3 的既有渲染零變動**；MoraChen 複審只需確認「additive、12.3 快照不變」。
- 導航一律用既有 react-router（`useNavigate`，模式同 `TaskDetailPage` 的 `<Link to={/projects/${id}}>`）；callback 的實作在 12.6 頁面，不寫進共用元件。
- 不改 `HistoryEventList`／`SourceEvidence`（直接用）。`HistoryEventList` 已把 `onAnnotate` 往下傳；本票順勢讓它把三個新 callback 一併透傳（optional、不傳即無），仍是 additive。

## 2. 12.6 專案歷程（頁面）

- **範圍（元件樹，照設計稿 §3）**：
  `ProjectHistoryPage`(資料容器；同頁支援全域／固定專案) → `HistoryHeader`(展示；頁名、專案資訊)、`HistoryFilters`(受控；draft 由容器持有、已套用取自 URL){`ProjectFilter`(僅全域；讀 ProjectListOut；全部／單點／指定專案)、`EventKindFilter`(八類、無預設評價)、`TaskFilter`(讀 TaskListOut、換專案清選)、`BatchFilter`(編號輸入＋列標籤捷徑、不做命名下拉)、`DateRangeFilter`(選填 from／to、既有 DatePicker)} → `HistoryResults`(容器；HistoryListOut、loading／error／empty) →【reuse】`HistoryEventList`→`HistoryEventRow`／`SourceEvidence` → `HistoryPagination`(展示；total／limit／offset)
- **關鍵裁定**：
  - **路由**：`/history` 與 `/projects/:projectId/history` **同頁、等價 query key**；固定專案頁不提供切換專案，**路徑專案範圍不被 URL 參數覆蓋**。兩條路由註冊於 `AppRoutes.tsx`（見 §5 協調）。
  - **按「套用」才查**；套用變更條件 → `offset` 回 0（第 1 頁）；全域頁換專案 → 立即清 draft 的任務選擇、套用後不送舊 `task_id`；**篩選寫 URL、不用 localStorage**；選項資料可依 draft 專案讀取，但不因此提前查事件、篩選不發任何業務 POST。
  - **filters 正規化唯一來源＝ `queryKeys.ts`（#55 已建 `normalizeEventFilters`）**，URL 解析／query key／請求參數同一份：全部專案＝省略 `project_id`；**單點任務＝字串 `"none"`（非 null）**；`limit` 預設 100 最大 500、`offset` 預設 0；固定專案路由把路徑 id 正規化成同一字串當不可切換範圍。專案 GET 與全域 GET 的相同條件**不可分成兩個 root**。
  - **任務篩選**＝下拉讀 `TaskListOut`（只取 id／目前 title，其餘欄位不拿來重寫歷程）；該端點無搜尋／分頁參數，不假設有。**日期 from／to** 選填露出（API 已支援），保持 `YYYY-MM-DD`、不對 ts 轉時區再前端過濾。
  - **批次**＝編號輸入＋事件列標籤捷徑（捷徑經 §1 的 `onBatchFilter` 帶入 batch_id、仍按「套用」）；不做命名下拉、不發批次清單端點。
  - **分頁**：依 total／offset／本頁筆數決定前後頁，翻頁把新 offset 寫 URL；**沿伺服器 ts DESC／id DESC，前端不重排**。
  - **三態**：loading 保留標題與篩選、結果區標載入中、**不假設 total=0**；error 用既有 `ErrorBanner`、可重試 GET、保留輸入、**NOT_FOUND／權限錯誤／成功零筆三者分開、不自動重送**；empty 僅 `items=[]` 才顯「無符合歷程」，過大 offset → 回有效頁重讀、不清其餘篩選。
  - **八種 kind 全顯示**；due 用 `effective_mark`、其他類型 `effective_mark=null` **不誤顯示為待補註記**；`task_title` 空字串依 **DA-05 顯示「—」**；`project_id=null` 範圍標為單點任務。
  - **唯讀頁、無任何寫入**；12.3 的補註記／改期／基準更正成功時，經 #55 統一失效層更新 `events` root，本頁自動反映、保留所有原事件並重讀有效註記。沿既有 QueryClient 禁焦點重讀，不新增輪詢。
  - `source.purged=true`→「（原文已依設定刪除）」、`purged=false & quote=null` 不誤稱清除（`SourceEvidence` 已處理，直接用）；`extra` 視為未知結構、不解析成完成回報／目標面板。
- **契約（全用重生成型別）**：
  - `GET /events → HistoryListOut`（params：project_id 十進位字串／`none`／省略、kind 八值／省略、task_id／batch_id int 選填、from／to date 選填、limit 1–500 預設 100、offset ≥0 預設 0；回 `items: HistoryItemOut[]`、`total`）
  - `GET /projects/{project_id}/history → HistoryListOut`（專案 id 由路徑固定，其餘參數同上）
  - `GET /projects?include_archived=true → ProjectListOut`（**僅全域頁**；含封存專案）
  - `GET /projects/{project_id} → ProjectDetailOut`（專案情境頁標題／封存資訊；**非歷程總筆數來源**）
  - `GET /tasks?project_id= → TaskListOut`（任務下拉）
  - `HistoryItemOut`＝EventOut 21 欄 ＋ `project_name: str|null`、`effective_mark: Mark|null`、`source: SourceRefOut`；`SourceRefOut`＝`label／quote|null／purged`。
- **界線**：不 import 12.1／12.3 頁面、不另建歷程元件副本、不加搜尋／cursor 參數、不解析 extra 自造欄位、不在歷程頁加修改原事件或刪除原文的按鈕（寫入屬 12.3、清除屬 12.14）。
- **驗收重點**：AC-11（無事件更新／刪除操作）、AC-27（組合篩選正確、total 正確、`project_id=none` 只查單點任務）、AC-28（source.purged／quote）、AC-29（task_title／mine 不被目前任務覆蓋）、DA-05（空 task_title→「—」）＋ 三態／URL 還原（初入與上一頁／下一頁）／分頁邊界（過大 offset）／**L1 錯誤路徑回歸**。MSW fixtures 一份來源、handlers 引用。AC-56（效能）屬後端／整合環境量測，**本票不以 MSW 回應宣稱已通過**。
