## 1. 本票核心裁定｜`GanttChart`（#36）怎麼接（先讀）

阿想已讀 main 上 `GanttChart` 實際碼，現況如下，施工按此接、勿改元件：

- **位置**：`frontend/src/features/project-overview/gantt/GanttChart.tsx`（已在本頁 feature 夾下）。12.1 的頁面檔同放 `features/project-overview/`，掛它為子元件、**不新建甘特元件**。
- **簽章**：`GanttChart({ gantt: GanttOut, width?, rowHeight?=64, leftLabelWidth?=280, dayWidth?=28 })`。吃**整包 `GanttOut`**（不是拆開的 rows）→ 頁面只需 `<GanttChart gantt={data} />`。
- **純 SVG、無 callback**：元件自己不讀 API／快取／系統日期、不接操作回呼（註解明載）。所有互動（改期、連結）由**頁面**負責，不塞進 `GanttChart`。
- **空圖已自理**：`range===null || rows.length===0` 時元件自繪「此專案尚無可繪製的時間資料」。→ **頁面不要重算或虛構 range**；頁面層的 empty 只負責 TaskTable「無任務」訊息與 summary 照回應顯示。
- **today 感知範圍**：元件內 `from=min(today, range.from)`、`to=max(today, range.to)`、提前用 `delta_days` 負值文字 → **頁面不重算 range／delta／提前天數**，直接傳伺服器值。
- **資訊可讀性**：SVG 的視覺資訊（狀態、延後、完成）在 `TaskTable` 也要讀得到，不能只靠顏色。

## 2. 12.1 專案現況（頁面）

- **範圍（元件樹，照設計稿 §3）**：
  `ProjectOverviewPage`(資料容器；**只** `/projects/:projectId`；持有 data＋selectedTaskId) → `ProjectHeader`(展示；`ProjectDetailOut`；專案歷程連結)、`ProjectSummary`(展示；只讀 `GanttSummary`)、`ProjectTaskWorkspace`(展示；共用同一份 `GanttRowOut[]`){`TaskTable`(展示；任務詳情／改期／整批順延入口)＋`GanttChart`(#36 元件)}、`DueAdjustmentSlot`(掛既有 `AdjustDuePanel`，面板自抓任務／原因)
- **關鍵裁定**：
  - **只做 `/projects/:projectId`**；**不做 ProjectPicker、不做 `/projects` 選擇頁**、不新增專案選擇查詢。無效／NaN id 不發請求。
  - **候選數分離（AC-34）**：`open_candidates` 採 B 口徑（只計已對應本專案的 open 候選，未配對不計）；UI 固定標「**已對應本專案的待確認候選**」，與正式數字分開、旁註「不計入下方數字」；**不以 `rows.length` 代替任何統計**、不自算完成率。
  - **改期入口**：列上直接展開既有 `AdjustDuePanel`，**只傳 `taskId`／`onDone`／`onClose`，不預填新日期、不加預填 props、不擴充 Dev-A 元件**；新日期／原因／註記由使用者在面板選；不先在格內選日期再轉交。成功 `onDone` → 使**本專案 gantt 失效**（`keys.gantt(projectId)`）、原面板既有 tasks 失效行為不改；取消關閉不送請求、不改 rows。
  - **STALE_VERSION**：沿既有面板重讀、清空輸入由人重做、不自動重送；並重讀甘特以免表格留舊日期。
  - **原訂日期只經 12.5 兩段式基準更正改**；本頁**不做可編輯欄位**。`delta_days`／`summary` 讀伺服器值、**前端不重算業務統計**。
  - **禁**：拖曳改期、縮放控制、完成率百分比（#36 元件也無這些，勿加）。
  - **連結**：專案標題→專案歷程（`/projects/:projectId/history`，12.6）、任務標題→任務詳情（`/tasks/:taskId`，12.3）；**只連結、不 import 12.3／12.6 頁面**；共用歷程元件由 12.3 建、本頁不另建。整批順延入口連既有 12.4 頁（不在本頁重做交易）。
  - **query key**：`keys.gantt(projectId)`（#55，root=gantt、序 gantt/project/projectId）；專案資訊沿 `keys.project(projectId)`；改期面板任務沿 `keys.task(taskId)`＋既有 fetchTask，**不把 `GanttRowOut` 塞進 `keys.task` 冒充完整 TaskOut**。
  - **三態**：loading 保留頁名／導覽、**不先顯零計數**、重讀標更新中；error 用既有 `ErrorBanner`、**NOT_FOUND 與空專案分開、不轉 rows=[]**、重試只重讀 GET；empty 僅成功 `rows=[]` 才顯「無任務」、summary 照回應（**不抹候選訊息**）、`range=null` 由 `GanttChart` 自顯空圖、不虛構範圍。
  - **日期**：`FromToDate` JSON 鍵 `from`／`to`（**前端不可寫成 `from_`**，後端 alias 才是 from_）；`YYYY-MM-DD`、不前端換時區。
- **契約（全用重生成型別）**：
  - `GET /projects/{project_id}/gantt → GanttOut`（`range: FromToDate|null`、`today: date`、`summary: GanttSummary`、`rows: GanttRowOut[]`）
  - `GanttSummary`＝`done／total／delayed／open_candidates: int`
  - `GanttRowOut`＝`task_id／title／owner／status(todo/doing/done)／start／orig_due／latest_due／delta_days／done_date(nullable)／blocked／version`
  - `GET /projects/{project_id} → ProjectDetailOut`（id／name／scope／audience／line_group_id／created_at／updated_at／archived_at／task_count／baseline_saved_at；**task_count 不拿來自算完成率**，摘要以 GanttSummary 為準）
  - 改期沿用生成 `AdjustDue` 請求／`AdjustDueOut`（task／event／warnings／needs_mark）。
- **界線**：不加完成回報／週報摘要、不為 Phase 9／10 預造欄位、不改 Dev-A／Dev-B 元件、不 fork `GanttChart`。
- **驗收重點**：AC-06（已完成改期遭拒）、AC-25（基準更正後依新原訂日重繪）、AC-34（候選數分離不汙染統計／甘特）、AC-01～04／07／12（改期原因/註記流程、STALE_VERSION 重讀）＋ 提前／延後／完成三種甘特列呈現 ＋ 三態（NOT_FOUND vs 空專案）＋ `range=null` 空圖 ＋ **L1 錯誤路徑回歸**。MSW fixtures 一份來源、handlers 引用；AC-56（效能）屬後端／整合環境，**不以 MSW 回應宣稱通過**。
