## DA-01 資料庫改用 PostgreSQL 【已複核：產品負責人 2026-11-16，#15】

- **決定**：PostgreSQL 15+（本機開發用 17）。spec 4.2 DDL、6.8、8.1–8.3 已改寫；todo 0.7、1.3、1.6 已改寫。原版可在 PR 的 diff 對照（`main` 上的 `docs/spec.md`、`docs/todo.md`）。
- **型別對應**：

  | spec 原寫（SQLite） | 改為 | 說明 |
  | --- | --- | --- |
  | 日期 `TEXT` | `DATE` | 日期差直接相減，`delta_days` 不必轉換 |
  | 時間戳 `TEXT` | `TIMESTAMPTZ` | 連線時區設 Asia/Taipei；API 輸出 ISO 8601 含 `+08:00` |
  | 布林 `INTEGER 0/1` | `BOOLEAN` | 實測原生 boolean 不收整數字面值 `1`；SQL 種子改寫 `true`／`false`，AC 中的 `mine=0` 讀作 `false` |
  | JSON `TEXT` + `json_valid` | `JSONB` | 型別本身保證合法；`levels` 用 `CASE` 檢查陣列長度 5 |
  | `INTEGER PRIMARY KEY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | 種子可指定 id；`seed_sql()` 結束時重設序列，避免之後的寫入撞號 |
- **只增觸發器**：除 UPDATE、DELETE 的列級觸發器外，另加 `BEFORE TRUNCATE` 語句級觸發器；PostgreSQL 的列級觸發器攔不到 TRUNCATE。
- **SQLite 專屬項目的對應**：
  - WAL、`busy_timeout`、單一寫入連線 → READ COMMITTED，加 `SELECT … FOR UPDATE` 鎖任務列與 `version` 比對；SQLSTATE `40P01`、`40001` 重試 3 次。
  - backup API → `pg_dump -Fc`，保留 14 份。
  - 每個測試一個暫存 SQLite → 每個測試由範本資料庫 `CREATE DATABASE … TEMPLATE` 複製一個獨立資料庫（實測約 0.2 秒）。原因是 `events` 不能 DELETE，測試之間清不掉；並行測試（3.9）和整批回滾（AC-17、AC-57）也需要真的 commit 與兩條連線。
- **`idempotency_keys.response`**：存 `{"status": 狀態碼, "body": 回應}`，重送時才能回傳相同狀態碼。欄位數不變，型別改為 JSONB。

## DA-03 `adjust_due` 簽名加兩個選填關鍵字參數 【已複核：產品負責人 2026-11-16，#15】

- **決定**：`adjust_due(session, task_id, new_due, expected_version, reason, note, mark, defer_mark, *, origin, batch_id=None, origin_ref=None, source_id=None) -> DueResult`。
- **原因**：FR-INB-10 要求延期候選的事件「依據為該候選與原句」，對應 `events.origin_ref`（候選 id）與 `events.source_id`。凍結簽名帶不進這兩個值，Dev-B 的 Phase 7 會卡住。新參數是選填關鍵字參數，既有呼叫方式不受影響。
- **影響**：todo 5.7 契約清單；Dev-B Phase 7.6。

## DA-04 `DueResult.needs_mark` 的單一定義 【已複核：產品負責人 2026-11-16，#15】

## DA-12 時間管理統計的判讀與精力分布 【已裁定：產品負責人 2026-11-16，#15；判讀細節待確認】

## DA-24 OpenAPI 文件需要 token，關閉 `/docs`、`/redoc` 【已複核：產品負責人 2026-11-16，#15】

## DA-25 未預期例外不寫入錯誤訊息與 traceback 【已複核：產品負責人 2026-11-16，#15】

資安審查發現：PostgreSQL 的錯誤訊息會原文引用輸入值，例如 `invalid input syntax for type integer: "<使用者輸入>"`。原本的做法是用 `exception_handler(Exception)` 回 500，但 Starlette 回應後會把例外再拋出，uvicorn 就把含這段訊息的完整 traceback 寫進 log，違反 CLAUDE.md 資安 3。

- 新增最外層的 `UnhandledErrorMiddleware`：只記錄例外類型名稱，回 500 `INTERNAL_ERROR`，不再往外拋。
- 資料庫引擎設 `hide_parameters=True`，SQLAlchemy 的例外訊息不帶 SQL 參數值。
- 取捨：除錯時看不到完整 traceback。需要時在本機用測試重現，不在正式環境開啟。

## DA-26 A1、B2、B5 以新遷移 0002、0003 實作 【已裁定：產品負責人 2026-11-15，PR #1 審查】

- **做法**：不改 0001，新增 0002（結構：移除 `AI-08`、`rubrics` 不可修改觸發器）與 0003（系統種子）。理由：符合「既有遷移只新增」，而且其他人的本機資料庫已跑過 0001，改 0001 會讓大家的結構悄悄不一致。
- **B5 的成本**：
  - 一個 plpgsql 函式加三個觸發器，與 `events` 同一種寫法。
  - 量表寫入只有「確認新版本」一條 INSERT 路徑，觸發器只擋 UPDATE、DELETE、TRUNCATE，對寫入沒有額外成本。
  - 降級（0002）會移除觸發器。
- **B5 對 QC 測試的影響**：
  - 測試隔離方式是每個測試由範本複製一個獨立資料庫，結束時整個刪除（DA-01），不靠刪 `rubrics` 清資料，所以觸發器不影響測試清理。
  - 唯一限制是測試裡不能 UPDATE 或 DELETE 量表；要不同內容就 INSERT 新版本。
- **B2 對既有測試的影響**：範本資料庫已含種子，插入 `settings(id=1)` 或 `rubrics(version=0)` 的測試種子會撞號。Dev-A 的測試已修正；QC 與 Dev-B 的種子請照 spec 4.2.1 的規則。
- **0003 降級不刪除種子**：量表受觸發器保護、也不該被刪；再升級時 `ON CONFLICT DO NOTHING`，仍各 1 列（AC-59）。
