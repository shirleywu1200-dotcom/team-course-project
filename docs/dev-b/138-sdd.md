# #138 第 1 點 SDD：AI-01 新舊日期相同的「延期」不建候選（Dev-B）

依據：spec FR-INB-07（R2 規則）、6.x AI-01 輸出規則（spec 第 673 行一帶）；#138；真實 AI 測試報告（2026-11-21，本機）。
狀態：**設計已定案（Q1＝A），等 PO 在 #138 同意 spec 變更後才動程式**（2026-11-21）。

## 0. 現況與問題

真實 AI（`claude-sonnet-5-5`）測試時，訊息「投影片我週末會趕完」被 AI-01 判成 `delay`、`new_due=2026-11-22`。但這個任務的 `latest_due` 本來就是 2026-11-22。

R2（`backend/app/domain/inbox/r2.py`）目前只檢查：輸出格式、對不對得到任務（AC-37）、日期能不能轉、日期範圍、語氣降級（AC-35、AC-36）。**不比對新日期與目前的期限**，所以這筆變成一張 `delay／sure` 候選，畫面寫「最新預計 2026-11-22 → 2026-11-22」。

**這不只是 AI 判斷不準，而是一張注定失敗的候選**：使用者按「確認」時，`confirm._apply` 會呼叫 `adjust_due`，而 `adjust_due` 遇到 `new_due == latest_due` 會丟 `NO_CHANGE`（`domain/due.py`）。也就是說，照預設日期確認一定報錯，使用者只能忽略或手動改日期。

## 1. 設計

### 1.1 規則

在 R2 加一條**確定性規則**，不靠 AI、也不靠提示詞：

> `kind=delay`，且 `new_due` 轉得出日期、等於該任務目前的 `latest_due` 時，**這則訊息不產生候選**（等同 `kind="none"`），計入「略過」。

- 放在「對到任務」之後、「日期範圍檢查」與「語氣降級」之前。所以就算訊息含「可能」，日期沒變也不會變成待釐清卡片。
- 只比對 `delay`。`done`、`stuck` 不受影響。
- `new_due` 早於 `latest_due`（提前）**不在本次範圍**，維持現狀：仍是 `delay` 候選，確認時照 `adjust_due` 現行規則處理。

### 1.2 程式改動

| 檔案 | 改動 |
| --- | --- |
| `domain/inbox/r2.py` | `apply()` 加關鍵字參數 `latest_due: Mapping[int, date] \| None = None`；`_draft()` 在對到任務後，若 `kind == "delay"` 且 `new_due == latest_due.get(task_id)` 則回 `None` |
| `domain/inbox/ingest.py` | `_payload()` 多回傳 `{t["id"]: t["latest_due"]}`；`r2.apply(...)` 帶入 `latest_due=` |

- 用**關鍵字參數加預設值**，既有呼叫端與 `test_phase7_rules.py` 的 `apply()` 小工具都不用改（「測試不遷就實作」）。
- 不改 API、不改資料表、不改 AI-01 提示詞與 payload。`latest_due` 本來就在 payload 裡，現在只是讓 R2 也拿到同一份值。
- 比對的是**送給 AI 當下**的 `latest_due`。如果 AI 呼叫期間任務剛被改期，以送出當下的值為準。這種競態只會讓結果多一張或少一張候選，不會寫錯資料：候選要人確認才生效，確認時 `adjust_due` 還會再檢查一次。

### 1.3 spec 寫回（要 PO 同意）

- **FR-INB-07**：「無關訊息略過並計數」後面補一句：「延期的新日期等於任務目前的預計完成日時，視為沒有變動，略過並計數（#138）。」
- **6.x AI-01 輸出規則**（第 673 行一帶）：`kind="none"` 那條後面補同一條規則。
- AC 不新增編號，測試名稱掛 `#138`。

## 5. 討論決議

- **D-1（2026-11-21 Mora）Q1 採 A：同日「延期」直接略過**，不降級成待釐清。架構後果：(a) R2 多一條「降級到不產生」的規則，符合「只降級不升級」(b) 收件匣不會出現必定報 `NO_CHANGE` 的卡片 (c) 被略過的訊息只反映在摘要的「略過 N 則」，使用者看不到個別原因。
- **D-2（2026-11-21 Mora）Q2：PO 同意就做**；11/23 晚上前合併不了就記為已知限制。
