## 2. 資料流

```
GET /candidates?state=open ──┐
GET /settings（confirm_cap_min）┤→ InboxPage ─ 分區 → CandidateCard × N
                              │
POST /ingest ─ sync → 回傳候選 → 失效 candidates 查詢
             └ async → job_id → 每 2 秒 GET /ingest/jobs/{id}；succeeded/failed 或超過 60 秒停止
CandidateCard 動作 → POST /candidates/{id}/confirm|clarify|create-task|ignore
  └ 回 needs_mark=true → 卡片內開註記（MarkChoice＋ReasonSelect），送 POST /events/{event_id}/annotations 或選「稍後」
```

- **單一事實來源**：候選清單只從 `GET /candidates` 的查詢快取來；任何動作成功後失效 `["candidates"]` 與 `["tasks"]`，不在元件裡另存一份清單。
- **分區**由 `kind` 推導：`delay`／`done`／`stuck` → 待你確認；`unclear` → 待釐清；`unmatched` → 待配對。純函式 `groupCandidates`，單獨測試。
- **樂觀鎖**：`confirm`、`clarify` 帶卡片上的 `task.version`。收到 `STALE_VERSION` 重新載入候選，讓使用者重按（CLAUDE.md 前端 5），不自動重送。
- **冪等**：每次按下產生一個 `Idempotency-Key`（沿用 `newIdempotencyKey`），按鈕送出期間停用。
- **原句已清除**：`quote` 為 `null` 時顯示「原句已刪除」（Phase 8 清除後）。

## 3. 卡片行為（依原型 `candCard`）

| 種類 | 顯示 | 主要動作 | 次要動作 |
| --- | --- | --- | --- |
| `delay` | 原句、任務、最新預計 舊 → 新（日期可改）、「原訂不會被覆寫」 | 確認 | 忽略 |
| `done` | 狀態 → 完成 | 確認（成功後提示「完成回報可到今日頁補填」） | 忽略 |
| `stuck` | 狀態 → 卡住 | 確認 | 忽略 |
| `unclear` | AI 的 `note` 與建議 | 依建議確認（`suggest` 為 delay 時日期可改） | 忽略（原型把忽略設為主要按鈕，避免誤採用） |
| `unmatched` | 標題、負責人（發言者）、期限欄位 | 建立新任務（標題、期限必填，期限不預填） | 忽略 |

- 期限不預填：FR-INB-14「期限由你確認」，避免使用者沒看就按。
- 註記：只在回應 `needs_mark=true` 時出現，三選一與原因都不預選（FR-AI-06）；「稍後」直接收起，不呼叫 API。

## 4. 錯誤與降級

| 情況 | 畫面 |
| --- | --- |
| `ai_status` 不是 `ok` | 「AI 解析失敗，可手動建立任務」，原文已保存（AC-40） |
| `unparsed_lines` 非空 | 列出行號，提示修正後重貼 |
| 413 `PAYLOAD_TOO_LARGE` | 提示超過 20,000 字 |
| `CANDIDATE_NOT_OPEN` | 重新載入清單（可能在另一個分頁處理過） |
| `TASK_DONE`、`DATE_OUT_OF_RANGE`、`STALE_VERSION` | 錯誤橫幅（沿用 `ErrorBanner`，補三個訊息） |
| 輪詢超過 60 秒 | 「仍在處理，稍後回收件匣查看」（spec 6.1） |
